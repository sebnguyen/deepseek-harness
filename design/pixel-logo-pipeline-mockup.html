Pixel mark pipeline — original vector → hard downsample → window sample → vector squares

Is the method wrong?

No — this page runs exactly that pipeline, live, on the real website/public/favicon.svg path. Three refinements fell out of implementing it:

  • How you sample the window matters once features get small. At 24×24 and 16×16, threshold 50%, a single centre sample and a whole-window alpha average agree to the cell (255 vs 256 cells). They diverge at 12×12 — the detached dot’s cells flip between the two readings — and at high thresholds, where centre sampling turns cells on that window averaging sheds as a few per-cent mass. Coverage is the honest reading.
  • The gap needs no per-size bookkeeping. Stored as a fraction of the viewBox unit, it scales with the mark automatically — the ratio is preserved for free. Widening the gap only below ~1px pitch is an optical tuning for tiny renders, not a correction of the method.
  • The shipped mark is hand-drawn ASCII, not derived. A true downsample matches GRID24 within 3 of 258 cells — close, but every logo tweak means re-eyeballing literals by hand. This pipeline derives the grid from the real path at any N (comparison at the bottom).

3 · Sample over each x×x window

window grid over the source — red windows are rejected
kept cells

Coverage mode averages the high-res alpha across the whole window and keeps the cell when the mean crosses the threshold; centre mode reads the single downsampled pixel instead. At 24/16 and 50% they agree; set N to 12, or raise the threshold into the 70–90% range, and watch the two readings diverge on the dot cells.

4 · Emit one vector square per kept cell


    
Each kept cell becomes one <rect> in a 0 0 N N viewBox. The gap is an inset of gap/2 per side in viewBox units, so it is ratioed with the scale by construction — zoom the next sections to any size and the margin keeps its proportion with zero extra logic.

The shipped recipe, imposed on derived rects unchanged: sweep buckets cells by angle into 16 groups, each <g> carries its own clockwise animation-delay on a shared step-end ladder; twinkle gives every rect its own seeded duration and negative delay. Animation targets the generated objects, exactly as the method intends.

  


  

    
6 · Scale infinitely — the gap ratio holds

    

    
One markup, many sizes. Because widths, heights and gaps all live in viewBox units, the gap-to-pixel ratio is identical at 12px and at 240px. Drag the gap slider: every size updates in the same proportion.
