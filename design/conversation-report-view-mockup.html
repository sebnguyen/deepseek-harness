Turn report view — the session reads as a report, not a tape

A redesign of the chat/conversation surface of the DSH web client (packages/client/ui-chat, ui-tool, ui-quiet). Tokens, hairlines, elevation and frame chrome are lifted from the live theme so the mock renders on the shipped design language.

What the current transcript gets wrong. The column is a tape of equal-weight rows: user bubble, Think fold, tool frames, retry rows, turn tail. Folds (step spans, process rail) hide work but never summarize it; quiet modes hide steps with, in the code's own words, “no summary node anywhere”. The answer lands last, after the evidence for it, so every turn reads investigation-first. Files touched are scattered across write frames, and a long session has no scannable shape — TurnNavigator jumps between turns but never says what a turn was.

The proposal. Keep the tape (it is the source of truth) but add a default report view: each turn becomes intent → answer → artifacts → evidence, with the stock tool frames re-homed — unmodified — under verb-grouped summary rows, and a session outline rail that makes the whole conversation scannable in one viewport. Verification is one click away at every level.

1 · The session as a report interactive

One real session in the new shell. The outline rail answers “what happened in this session” before you scroll: one row per turn with status and wall time, plus an aggregate of touched files at the foot. The segmented control flips between Report (default) and the stock Transcript — same data, two readings. Try the toggles: view mode, evidence folds, theme.

Report mode quiet: normal model · deepseek
  • Answer first. The closing answer of a turn is hoisted to the top of its card; the tape still ends with it, report view leads with it.
  • Groups answer “what kind of work, what outcome”. Verb + object + count + duration, status folded into the count (1 failed → 1 passed); the step-span fold grammar of design/chat-span-fold-mockup.html supplies the ranges, this view adds the summary node quiet mode never had.
  • Frames re-home, never rewrite. Inside a group row the stock labeled frame — [i/N] header, exit-code marker, purpose line — renders byte-identical, so anything verifiable today stays verifiable.
  • Decisions stand. Approvals, user questions and escalated permissions are never folded; they card outside the evidence body with their outcome.
  • Live turns degrade gracefully. While a turn runs, the card is a skeleton: groups assemble as spans settle, the answer slot fills at finish.

2 · Why not just quiet mode rule

Quiet/Silence suppress rows; report view re-describes them. Suppression is a volume knob — the reader who hides the process also loses the outcome counts, the failed-then-passed run, the files touched. The report is derived state over the same event stream (step/start, tool/result, turn tail), so Normal/quiet/report are three projections of one truth, and the outline rail is the projection of the whole session. Ship order: groups + rail behind the segmented control first (additive), then report as the default once groups cover every tool kind.
