# Agent Note: Diff-scoped shape guards — mechanical over-abstraction and readability checks on agent edits

Status: proposed

## Problem

The complaint this note addresses is not correctness: models are overzealous with helper functions. They extract module-local helpers with exactly one call site, write pass-through delegations, and re-implement utilities the codebase already has, and the resulting indirection is what makes the code hard to read while every lint and type gate stays green. The research gives the pattern a name and a signature. [AI-Generated Smells](https://arxiv.org/html/2605.02741) finds LLM code marked by method bloat, redundant implementation, and a "Modular Mirage" — file and function separation without semantic cohesion — with functional correctness decoupled from those defects, and structured few-shot prompting unable to mitigate the decay. The [drywall](https://github.com/nikhaldi/drywall) plugin exists because coding agents show a bias toward producing new code over reusing or extracting what exists. Readability is not a matter of taste for enforcement purposes: structural features — line length, nesting, identifier verbosity — predict human readability judgments (Buse and Weimer's [readability model](https://dl.acm.org/doi/10.1145/1985441.1985454) and its [general successor](https://web.eecs.umich.edu/~weimerw//students/dorn-mcs-paper.pdf)), which is why shape enforcement lives in AST checks, the same place the industry puts it via [custom lint rules](https://neciudan.dev/master-eslint-rules). And the [rule-of-three argument](https://www.linkedin.com/posts/randyshoup_not-dry-but-the-rule-of-three-instead-activity-7308790229690134528-Sk-d) inverts the usual framing: premature abstraction, not repetition, is the costlier mistake, so a one-off helper needs a reason to exist, and the absence of that reason is the machine signature.

This repository already names the smells in prose and audits them on demand. [packages/AGENTS.md](../../../../packages/AGENTS.md) calls a public service method with one internal caller an inverse smell and prescribes a private closure; the [dependencies-over-hand-rolling decision](../../implemented/process/2026-07-26-dependencies-over-hand-rolling.md) treats reuse as policy; the [dsh-find-simplifications skill](../../../skills/dsh-find-simplifications/SKILL.md) classifies symbols by their consumers, its strongest simplification candidates being exactly the single-caller helper and the unused abstraction. But prose is compliance and the skill runs only when invoked, over the whole repository; nothing watches the diff at write time. The seams to change that are shipped and typed: `tools/post-execute` attaches model-visible `additionalContexts` or blocks with feedback, and `agent/turn-stopping` plus `agent.steer()` requests a bounded extra step, per the [interception extension-points Agent Note](../../implemented/feature/2026-06-30-interception-extension-points.md). The external approximation — Claude-Code-style hooks whose exit-2 blocks an action — is coarser on every axis by the [hook-protocol library's own record](../../archived/feature/2026-06-30-hook-protocol-lib.md).

## Proposal

Two function plugins join the `guard/` group (whose scope sentence widens from loop hygiene to behavior guards in the same change), disabled in shipped profiles, every deployment-varying choice a validated `Config` field. Detection draws each check from the cheapest source that can answer it: the configured language server of the `lsp` group for everything referential, a local parse over the changed function's text for body shape, and jscpd from the existing `duplication` gate for clone detection per the prefer-maintained-dependencies policy. `ctx.lsp`'s four shipped normalized operations — definition, references, implementations, hover — cover the referential share as-is; the protocol's `callHierarchy` incoming-calls would refine mentions into callers and stays a possible one-operation seam addition, not a requirement. Deployments supply their own servers and the group ships none, so every LSP-derived signal carries a TypeScript compiler-API fallback producing the same counts offline, and a deployment with no server configured gets the fully local analysis. A new symbol is one added since the session-start baseline, which scopes every finding to what the agent wrote and leaves pre-existing debt to the skill.

The maintainable share stays maintained. Clone detection is jscpd exactly as the existing `duplication` gate runs it. The readability thresholds are ESLint core rules that already ship off — `max-len`, `max-depth`, `max-lines-per-function`, `id-length`, `complexity` — configured on over the touched hunks. Zero-use dead code is `@typescript-eslint/no-unused-vars` today and [knip](https://knip.dev/typescript/unused-exports) at audit time. The guard therefore owns no parser and no metric math; the residue no maintained rule will ship is two vendored minimal ESLint rules — because a helper with exactly one caller is by default legitimate, so no general-purpose linter calls it a violation — a reference-count rule reading the scope manager's `variable.references` for the *exactly one* case, and a pass-through rule whose identical-body twin is covered by [eslint-plugin-sonarjs/no-identical-functions](https://github.com/SonarSource/eslint-plugin-sonarjs/blob/master/docs/rules/no-identical-functions.md) while a delegating-call body needs its own structure walk. The plugin's own code is the diff scoping, the ESLint and jscpd orchestration, and the advisory and steer strings.

### `post-edit-shape` — advisories at the write

A `tools/post-execute` listener whose configured matcher selects file-mutating tool calls. After each accepted write it diffs the touched file against the baseline and runs four checks over the added or changed functions: **single call site** (LSP-owned — `findReferences` over the new symbol counts project-wide uses, and exactly one same-file reference on a declaration whose export keyword is absent from its text is the advisory, zero references being the dead-code twin the same count catches and already enforced today by `no-unused-vars` and by knip at audit time; with no server configured the compiler-API project scan yields the same counts), **pass-through** (LSP-assisted but locally decided — hover or definition at the body's sole invocation names the delegation target, but no protocol request reports body structure, so the guard parses the changed function's own text to ask whether the body is that one call with arguments merely reordered), **clone** (jscpd token similarity against existing repository symbols, because no protocol request names similar code, while `goToDefinition` and hover verify the named reuse target is real and print its signature into the advisory, with the [lsp-folder-map proposal](2026-09-21-lsp-folder-map.md) its richer symbol source if that ships), and **readability regression** (ESLint core thresholds that ship off by default — `max-len`, `max-depth`, `max-lines-per-function`, `id-length`, `complexity` — configured on over the touched hunks, because line length, nesting depth, and identifier length are the text-and-AST features the readability literature weights and no language-server query answers). All four surface as `additionalContexts` — one line each, naming the symbol and the options — and none blocks: the opposite of overzealousness would be judgment-free inlining, and a hard block on shape turns the model into its inverse failure. A shaped start is also expressible externally as custom ESLint rules run by the existing hook bridges, but diff scoping and the resolve-or-justify semantics below have no expression in exit codes, which is why the native plugin is the design.

### `done-gate` — one mandatory simplification pass at the stop boundary

An `agent/turn-stopping` listener re-reads the turn's touched files and resolves each advisory the mechanic way: the symbol disappeared, it was replaced by a reference to the named existing symbol, or the symbol carries a tagged one-line rationale using the repository's tagged-marker semantics — `TODO(single-caller)` or `TODO(clone)` beside the declaration, one sentence on why the abstraction earns its keep. Every unresolved item becomes a single `agent.steer()` that lists them with those three resolutions, for a configured `maxContinuations` defaulting to one: the model may keep every helper it wrote, but it must say why, and that sentence is precisely what overzealous generation skips and human review wants. Beyond the bound the turn closes with the unresolved list logged and surfaced in the user-visible outcome, so the gate neither ends silently nor pays for the same smell twice.

### Language portability — one advisory seam, per-language exporters

The machine signatures are not JavaScript phenomena, and every language the agents touch has its own row of maintained exporters, which the guard keys by file extension exactly as `lsp-stdio` keys language servers. Go's row is the fullest: [golangci-lint](https://golangci-lint.run/docs/linters/) ships the twins of every ESLint rule the guard configures — `funlen`, `lll`, `nestif`, and `gocyclo` or `cyclop` for the readability thresholds, `dupl` for clone fragments per its [dupl settings](https://golangci-lint.run/docs/linters/configuration/), and the staticcheck unused family for zero uses — and gopls answers the reference counts. Rust's row is clippy's `too_many_lines` and `cognitive_complexity` with rustc's `dead_code` and rust-analyzer; Python's is ruff's length and complexity rules with pyflakes unused plus [vulture](https://github.com/jendrikseipp/vulture) for dead code and pyright. The cross-language clone detector is [PMD CPD](https://pmd.github.io/pmd/pmd_userdocs_cpd.html), whose copy-paste table spans Go, Rust, Python, and the C-family, while jscpd stays the runner where the repository already runs it. Reference counting is the one genuinely uniform axis — one `ctx.lsp` implementation serving gopls, rust-analyzer, pyright, and the TypeScript server alike — and the pass-through residue stays per-language and small, so a deployment whose language has no exporter at all gets `ctx.lsp` counts plus the configured cross-language CPD and a degrade annotation for the rest.

### Configuration and degradation

Validated `Config` carries the tool matcher, the baseline source, jscpd thresholds or inheritance from `.jscpd.json`, the line/nesting/identifier thresholds, the rationale-tag vocabulary, `maxContinuations`, and byte caps on the advisory and steer payloads so the guards' KV-cache effect per step stays bounded. A parse failure, a missing tool, a stalled or absent language server, or a timeout degrades to a logged non-blocking annotation naming the skipped check — the hook protocol's degradation rule applied natively, so a guard can never stall or crash the turn.

## Alternatives considered

- **Correctness wiring — post-edit lint/tsc plus a test-gated stop (this note's first draft).** Loses to scope: correctness is enforced by CI and by per-turn verification elsewhere, and the observed failure is shape that stays green under every correctness gate. The clone half of jscpd survives as the reuse check.
- **Aggregate quality platforms (SonarQube-style).** The smells study explicitly faults them for conflating superficial lint with structural smells, and they audit the whole tree where this design audits only the diff; a local AST over touched symbols is cheaper and pre-existing-debt-free.
- **An LLM critic judging extraction at stop.** Nondeterministic, token-expensive, and self-defeating: the complaint is that model judgment over-extracts, so the judge shares the defendant's bias. Admissible later only as bounded advisory texture over deterministic findings.
- **Hard-blocking the write on a shape smell.** Converts taste into compulsion: the inlining-fix loop, and abstractions deleted for the wrong reason. The forceful alternative — filtering or rewriting the visible input from pre-tool — is itself the deferred consistency problem owned by the [pre-tool input-rewrite proposal](2026-06-30-pre-tool-input-rewrite.md), one more reason to keep judgment and require its artifact instead. Resolve-or-justify keeps judgment but makes inattention impossible, which is the actual defect.
- **Hand-rolled metrics inside the plugin.** Loses to the prefer-maintained-dependencies policy: ESLint's scope manager and core rules, jscpd, and knip delete nearly all of the metric code the guard would otherwise own; the two vendored rules are the residue no maintained rule can ship.
- **Whole-repo audit at stop, i.e. the skill as a gate.** Pre-existing debt would drown the turn's contribution and burn continuations on smells the turn did not write; diff scoping exists to enforce only the machine signature, with the skill keeping ownership of the standing repo.
- **Stronger prose.** The smells study's few-shot ineffectiveness finding is the controlled version of what every harness observes anecdotally.

## Acceptance criteria

- `post-edit-shape` and `done-gate` ship as function plugins with validated `Config`, disabled in shipped defaults, each with a REAL composition test booted through the Loader that mocks only the executor and a `ctx.lsp` provider: a write adding a single-caller helper yields a post-execute context naming it, driven once by the mocked references provider and once by the compiler-API fallback with no provider configured; a turn stopping with it unresolved receives exactly one steer naming the symbol and the tagged-TODO escape; adding the `TODO(single-caller)` rationale closes the turn silently; a clone advisory names the existing file and symbol; a pass-through wrapper and an over-threshold function are flagged; a parse error degrades to an annotation.
- Unit tests at the threshold edges: functions at exactly the line limit, exported symbols excluded from single-call-site, zero- and two-call-site symbols unflagged, the baseline excluding pre-existing symbols, rule-tester cases for the two vendored ESLint rules at one, zero, and two references and for pass-through versus merely delegating bodies, and one Go-touched-file case proving the per-extension adapter row runs golangci-lint's corresponding linters with the same advisory strings.
- Every advisory and steer string appears in the session log; the generated config catalog gains both plugins; the guard group README names the widened family.

## Risks

- False positives on legitimate one-off abstractions that exist to be named: the tagged rationale is the sanctioned escape and is reviewable in the diff like any comment; thresholds stay in `Config` for tuning.
- The model boilerplates the TODO marker without thought: the rationale is prose a human reads in review, the earlier failure was that no reason reached the diff at all, and a later audit can count markers per PR to catch gaming.
- AST cost on large files: checks run over added hunks' symbols with the configured timeout and the degrade annotation.
- Advisory fatigue: payloads are byte-capped and each advisory is one line naming the symbol and its resolutions.
