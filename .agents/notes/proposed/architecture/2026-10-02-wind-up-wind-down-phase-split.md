# Agent Note: Wind-up and wind-down as separate agent contexts

Status: proposed

## Problem

A dsh session runs the whole task in one context. The wind-up (exploration: tool calls, file reads, environment discovery) and the wind-down (producing the fix) therefore share one transcript, and every wind-down turn re-submits the entire wind-up history at the cache-hit price. The per-turn bill is `fresh + hit * accumulated prefix`, so the wind-up transcript is the base of a multiplier that compounds over each wind-down turn: with discovery pool `xd + yd` and `K − D` solving turns, the discovery tokens alone are re-billed roughly `(xd + yd) * ((D − 1) / 2 + (K − D))` times in token units. Output is billed at 3× input ($6/M vs $2/M on qwen3.8-max list price, $0.2/M per hit token at that input price), and because the agent is a black box, part of the wind-up output is never used by the fix — the provider bills it and its echo regardless.

Within that bill the two phases have opposite economics. Wind-up output tolerates waste: it buys information, and its useless fraction is only expensive because it also rides in every later prefix. Wind-down output tolerates none: it is billed at the output price and nothing ever re-reads it, so every unnecessary byte of the fix is pure loss. The same context hides this asymmetry from the harness: phrasing like "explore first, then fix" lives in prose, the wind-up garbage stays billable in every later turn, and the exit from exploration is a hope, not a logged state.

The shipped source already contains every seam the split needs — [plan mode](../../implemented/simplification/2026-07-22-plan-specific-collaboration-state.md) (explore before executing, exit only by handing over an approvable plan), [subagents](../../implemented/feature/2026-07-28-continuable-subagent-conversations.md) (a child whose context dies with it), compaction, todo, guard, preset, and per-phase system-prompt context — but nothing composes them around the phase boundary, and no Agent Note names the boundary as the cost lever it is.

## Proposal

Put each phase in a different prefix. The boundary is schedule state, not prompt text, and it commits through existing seams only.

**Wind-up runs in a throwaway head.** A one-shot direct child owns exploration. Its tool results and reasoning die with its context; the parent receives only the child's distilled findings. The parent's `discovery rereads` multiplier then applies to the handoff size, not the exploration pool: for a 5k-token handoff and a 20-turn parent at the 10% hit rate, the echo is on the order of a few cents of billing regardless of how fat the child's exploration was. Plan mode inside the child gives exploration an exit contract: `exit_plan_mode`'s plan is exactly the handoff document.

**The wind-down turns are minimal by construction.** The parent applies the approved plan and nothing else. A phase-scoped system-prompt segment (authored under `context/agent-instructions` conventions) states what a wind-down turn may output: patch hunks that edit files, input-generating actions (test runs, greps) whose results are read but never restated, and a final message that references deliverables rather than repeating them. The todo list doubles as the wind-up's exit criteria, so "done exploring" is an inspectable state.

**If the deployment keeps one context, rely on the composed safety nets.** Without delegation the wind-up garbage is in the prefix and compaction remains the only shrink: pressure-based `compaction-basic` as the floor, the [recallable backend](../feature/2026-07-06-recallable-compaction.md) as the better one with shadowed-but-reachable originals. Harness-fired compaction at the boundary belongs to the rejected boundary-tool family: once the explorer category exists its only job is rescuing a composition that chose not to delegate, and the preset therefore offers the split as the primary wiring instead of patching single-context after the fact.

**The border is enforced where the loop sees it.** A guard-package plugin classifies tool calls per phase — discovery-class calls (broad reads, environment probes) are flagged on wind-down turns, output-class calls (applied patches, final writes) on wind-up turns — and the plan-mode state is the phase switch the plugin reads.

**The wind-down is as short as the fix's success rate allows, and the saved turns are cheap only after the base is small.** Turns exist to raise the probability that the fix lands (checking intermediate results, catching a bad first attempt); they never shrink the fix itself. Once the handoff or its summary bounds the prefix, each extra wind-down turn costs roughly `hit * handoff` instead of `hit * (xd + yd)`, which is the difference between the flat line and the quadratic climb.

No new package. The work is a shipped cordis preset composing the packages above, the two phase prompt segments, the guard classification, and per-package README/JSDoc lines stating each package's role in the split.

### The child shape: read-only reader, cheap routable route, bounded spawning

The wind-up child is not a general delegable but a read-then-handoff reader, and [tool-subagent](../../../../packages/subagent/tool-subagent/README.md) today carries its three controls as instance config. `toolFilter` prunes the child's tool catalog to read tools, so it owns no write surface and its returned final text is its only product. `maxDepth` (default 3, `0` forbids delegation) stops children spawning their own exploration armies, and the `one-shot` foreground default means each child bill lands in front of the parent before the next can start. With `modelSelectionSettings: true` the call exposes optional `provider`, `model`, and `reasoning_effort` against the settings-owned exact-route allowlist: the parent can route the child onto a cheap non-thinking model while keeping its own thinking route, and denial of an unlisted route happens at the allowed-route assertion and the live-adapter preflight before the child is created — providers without `agentOptions` reject selection outright rather than ignore it.

Spawning-spree hygiene is the one genuinely missing piece. The shipped [guard](../../../../packages/guard/README.md) group's `repeat-tool-reminder` notices the exact same call repeated, not a spree of distinct spawns, and nothing counts delegations per turn. The composition therefore layers two brakes: the wind-up prompt segment names the child budget (one child per unknown class, re-spawning only when a run returned nothing usable), and a proposed small guard plugin in the guard group's loop-hygiene lineage counts delegation starts per turn and denies above a configured cap with a reminder that points at the handoff — denied in the guarded tool pipeline, not as a prompt hint.

### The explorer category and the parent's delegation discipline

The split's only new vocabulary is a sub-category of child, not a package: a second [tool-subagent](../../../../packages/subagent/tool-subagent/README.md) instance named `explore` whose [persona](../../../../packages/preset/persona/README.md) states the category's sole task — read the named unknown and return the findings, nothing else — and whose config freezes the child shape: `toolFilter` pruned to read tools, `enableRunInBackground: false`, `maxDepth: 1`, and the allowlist route below. The read-only shell rides on the child session's `read-only` sandbox mode set through the per-session setter at child composition, matching the per-spawn-sandbox-argument rejection above; the category is configuration, and its name is the persona's, not the code's. It adopts the Claude Code Explore pattern — one-shot, read-only catalog, cheap non-thinking route, findings as the only product — and exploration closes by the foreground return: no model-facing compact tool is needed to end the wind-up phase because a catalog that cannot write has no amnesia for a tool to mediate. The handoff itself is schema-gated: the instance config carries a deployment-owned `outputSchema` on `SubagentStartRequest`, the driver validates the capture against a byte-stable object schema, and `run.result.structured` is what the parent receives — free text neither counts as a handoff nor slips past the ceiling, while a child that finishes without a valid capture settles as an errored delegation the parent treats as unusable. The child never writes its own handoff, and the loop needs no change to make that true: two shipped hooks compose it. The loop ends a turn when an assistant step carries no pending tool call, and the serial `agent/turn-stopping` dispatch fires right before that break, so a driver listener there runs `agent.steer()` with a finish-now directive that keeps the turn alive for exactly one more step; the per-request `agent/request` waterfall then attaches the instance `outputSchema` as `structuredOutput` to that steered step's config, and the canonical request header carries the config by reference to the adapter's native `response_format`. Every run therefore terminates in one schema-forced API call carrying the child's full prior context, and the validated JSON of that call is the one handoff; a second bare settling lands as `error`. The extra full-context read is hit-priced and appears as an explicit line in the Stage-0 oracle. The shipped `structured_output` capture remains the soft-provider fallback, and a run with neither settles errored so the parent respawns within its cap; and because the child auto-compacts, a configured step budget — steered return at the cap, denied pre-step beyond it, both through existing seams — is the brake on runaway that `maxTokens` alone cannot be. The `usage` chunks already logged with every assistant record are the input series for both evidence surfaces: a per-agent and per-subagent cost chip in the Web GUI, folded and priced per scope, and the offline Stage-4 fold that compares branch-off against in-session discovery on real provider usage.

The parent-side system-prompt segment teaches spawning with intention. It names the catalog of unknowns the explorer exists for — one explorer per unknown class, each prompt scoped to what its read-only powers can answer, re-spawn only when a run returned nothing usable — and forbids the parent from exploring the same territory in parallel in its own context, since a parallel read is exactly the echo the split removes. The segment then names the return: the explorer's handoff arrives as the foreground tool result and the parent's next act cites it, converted into todo items and the plan, so exploration never continues into wind-down turns.

Waiting on the model return is the accepted latency price, and the design bounds it one knob at a time. The child's only product is the capped handoff, so the handoff ceiling is also the wait ceiling; the route sets the slope. Bench evidence from `inference-benchmarking-clickhouse` (synthetic 4k input / 512 output, single H100): `QWEN_2_5_14B_INSTRUCT` posts 12.2ms inner-token latency at concurrency 1 with a 209ms first token; `NVIDIA_NVIDIA_NEMOTRON_NANO_12B_V2_VL_BF16` ties at 12.9ms p50 and out-throughputs it under parallel readers (about 950 output tokens/s at 2 QPS). The tempting default, `QWEN_QWEN3_32B`, is the rejection case: 97ms per token and an 8.1s first token at concurrency 2 on MI325, in a family that carries the thinking mode the category excludes; `QWEN_QWEN3_CODER_30B_A3B_INSTRUCT` (41ms/tok) remains the fallback where only MI325 capacity is free. The Stage 3 allowlist default is the 14B, with the Nemotron entry behind the handoff-fidelity probe.

### Implementation stages

Staged by evidence, each gate failing closed into the current default. The split introduces no runtime vocabulary of its own; the only new source is the experimental prototype, one guard plugin, and a bench fixture — everything else is composition, configuration, and catalogs.

**Stage 0 — Cost oracle and fixture.** A bench scenario over a wind-up-heavy task runs the single-context composition and the split side by side, reporting provider-reported input tokens per turn against the closed-form oracle (the explorer's arithmetic in `artifacts/turn_cost_explorer.html`, mirrored as a script so the oracle and the report share one formula). Exit gate: the report shows the quadratic climb against the flat line on the same task, so every later stage bills against a measured target instead of a belief.

**Stage 1 — Child-shape fields plus schema pass-through, each at its owner.** `tool-subagent` gains three per-instance config fields — `outputSchema` (the deployment-owned handoff constant), `maxSteps` (the explorer's step budget), `childSandboxMode` (the child session's initial confinement) — and threads them onto `SubagentStartRequest`. The in-process driver enforces `maxSteps` (steering a return at the cap, denying the pre-step beyond it), writes the child's initial sandbox event from `childSandboxMode`, and keeps the shipped `structured_output` capture; `packages/llm` may add a native structured-output request passthrough so the wire grammar does the last verification of the capture. The phase texts ride shipped config — `plan-mode`'s `section` holds the wind-up segment, a preset persona line holds the constant discipline — and the catalog assertion that no compact tool is model-facing lives in tool-subagent's boot tests. No glue package remains: every piece lands on the package that already owns the adjacent behavior, with REAL-composition boot tests and per-file coverage as the fasteners.

**Stage 2 — `packages/guard/delegation-cap`.** The spree brake at shipped quality, in the guard group's loop-hygiene lineage: config names the delegation tool names and `maxDelegationsPerTurn`; the plugin counts delegation calls in the current turn's logged `tool/call` events and denies the cap-plus-one through the guarded tool pipeline with reminder text pointing at the handoff. The tool stays model-visible at the cap in the `maxDepth` pattern: the check is per call, not a hidden catalog edit.

**Stage 3 — Preset composition, zero source.** A documented preset under [packages/preset](../../../../packages/preset/README.md) composes the split from shipped parts: `plan-mode`'s deployment `section` receives the wind-up segment (so exit passes through approval), and two `tool-subagent` instances — the ordinary delegable and an `explore` instance carrying the explorer category (`toolFilter` read tools, `enableRunInBackground: false`, `maxDepth: 1`, child session `read-only` via `childSandboxMode`, plus `maxSteps` and `outputSchema`) — with `modelSelectionSettings: true` and the settings allowlist naming the measured non-thinking route (`QWEN_2_5_14B_INSTRUCT` default, `NVIDIA_NVIDIA_NEMOTRON_NANO_12B_V2_VL_BF16` behind the probe). The wind-down discipline rides the preset's `dsh-persona` line as constant prose; plan mode itself is the only state switch. The assembly-wide model-facing half now rides the shipped Core Rule `Explore Through Explorers` ([implemented note](../../implemented/feature/2026-10-02-explore-through-explorers-core-rule.md)), so assemblies without the preset still hear the trade whenever a delegation tool is mounted. Config-catalog and tool-catalog regenerate in the same change through `pnpm run gen-cordis-catalog`.

**Stage 4 — Evidence gate, then promotion or retreat.** The Stage 0 oracle runs over the Stage 3 preset; the handoff-fidelity probe scores the cheap route's handoffs against the thinking route on the same wind-ups. If both hold, the note moves to `implemented/` with its Proposal rewritten to present-tense Decision and the two packages leave experimental in the same change; if the probe says the cheap route loses, the allowlist default stays on the thinking route while the note remains proposed; if the flat-vs-quadratic delta does not reproduce on real provider usage, the preset ships off and the note records the miss with the measured numbers.

### Cost model

The explorer in `artifacts/turn_cost_explorer.html` implements the bill: fresh pools at full price once, accumulated history at `hit * P_IN` per turn, all output at `P_OUT`. The split replaces `xd + yd` inside the echo multiplier with the handoff size `h`, adding the child's own wind-up bill as a fixed term: `P_IN * (xd + yd) + P_OUT * yd + hit * P_IN * (xd + yd) * internal_fan`, flat in K. Single-context cost stays quadratic in K. Delegation wins whenever wind-down turns or the wind-up pool are large — the top-right of the K sweep.

## Alternatives considered

**Prompt-only phase discipline in one context.** The cheapest to attempt and the weakest: prose cannot remove tokens already in the prefix. The instruction text itself is re-billed every turn while the wind-up garbage it is supposed to neutralize keeps riding along. Rejected except as the wind-down output-discipline segment, which acts on bytes not yet written.

**Pressure-based compaction alone (current default).** Rejected as the boundary mechanism: its trigger is token pressure, a proxy that fires after the expensive turns have already paid. Kept as the safety net inside either phase.

**Recallable compaction as the phase boundary.** Partial complement, not a substitute: its stubs and state checkpoint make a one-context session's wind-down echo small, and it is the recommended single-context fallback here. It still bills the full wind-up once per turn until the first pass completes and pays per-pass summarize input; a child context moves the fat history out of the bill instead of condensing it after the fact. The two compose: recallable compaction handles overflow inside a long wind-up.

**Forking the subagent to run the wind-down.** Backwards: `subagent-fork` inherits the parent conversation, i.e. exactly the fat prefix this note removes. The child must own the phase that produces the garbage, which is the wind-up.

**Reusing `/compact` for model calls.** The command seam is user-initiated and audited as user intent; routing model calls through it muddles two actors in one audit and gives the model an unbounded-timing compact with no forced handoff argument — the pressure-proxy failure re-created on the model side, since the model sees token pressure no better than the harness does. A handoff-less `compact` is the same tool with its discipline removed: the argument is what converts amnesia into a state checkpoint.

**A per-spawn sandbox-mode argument.** Readonly children tempt a `sandboxMode` field on the delegation call, but sandbox mode is per-session state with a three-source precedence (approved per-call override, session event, deployment default) that a spawn argument would make a fourth source to arbitrate. The same outcome composes from shipped parts: `toolFilter` strips the write and exec tools, and the child session's `read-only` mode goes through the existing per-session setter where file-process confinement matters. Rejected as a new argument.

**A model-facing `compact` boundary tool.** Built up in an earlier draft of this note: one capped handoff argument, registered only while the wind-up section renders, harness-listener version included. Rejected in favor of the Explore pattern adopted above: the tool gave the model authority over its own prefix's amputation, its handoff-argument discipline recreated in prose what the explorer category gets structurally from a read-only catalog, and every boundary call paid one full-price reread of the rewritten prefix. With exploration out of the parent prefix entirely, the tool's remaining job was rescuing non-delegating compositions — which the pressure and recallable safety nets already own.

**An experimental phase-split glue package.** Earlier drafts reserved a private package to hold the phase sections, the step budget, the sandbox write, and the metrics fold. Rejected once the per-instance fields moved onto `tool-subagent` and the discipline text moved onto the persona line: nothing remained that shipped seams did not already own, and the leftover package would have been a second home for behavior whose owner already exists. Rejected as unnecessary; the gate plugin remains the only new runtime surface together with the tool-subagent and driver field deltas.

**A new package for hard phase gating.** Rejected per the plugins-not-loop-changes convention: every enforcement point above already lives on a documented seam (plan-mode state, guard plugin, preset composition), so a new runtime vocabulary would own behavior those seams already express.

## Acceptance criteria

- A shipped preset composes plan-mode, tool-subagent, compaction, and tool-todo such that a headless run of a representative fix task produces a session log in which wind-down turn requests contain the child's handoff (or the post-boundary summary) and none of the child's raw tool results; assert by reconstructing per-turn request input from the log and diffing against the single-context configuration's.
- Provider-reported per-turn input tokens for the split run match the delegated cost formula within measurement tolerance and stay flat across wind-down turn count while the single-context run climbs.
- The wind-down prompt segment pins byte-identical model-visible text and states the output discipline (hunks, referenced reads, non-restated results); wind-up exit criteria appear as todo items in the same session.
- The guard classification flags a discovery-class tool call issued after plan approval and an applied-patch call before it, in executor-denial tests, not prompt-side hints.
- Neither phase section exposes a model-facing compact tool; in the fallback composition compaction fires only on pressure or the user command, and where the recallable backend composes a keyless snapshot keeps originals `history_search`-reachable after a pass. The wind-up prompt section, the wind-down output-discipline segment, and the explorer persona are byte-identical static strings; the handoff ceiling and the cross-over gate are config.
- The reader child composed with `toolFilter` rejects an applied-patch and a shell write call through the executor with errored results, while the foreground one-shot returns only the child's final text; a per-spawn `model`/`reasoning_effort` selection against the settings allowlist runs a non-thinking route for the child, an unlisted route is denied at child creation, and the delegation-cap guard denies the cap-plus-one spawn of a turn while cap-minus-one passes.
- The `explore` instance's persona pins the sole-task text and the handoff ceiling as byte-identical strings; `enableRunInBackground: false` denies a forced background explorer through the executor; the explorer child's session runs under `read-only` with every non-read tool call denied.
- plan, subagent, compaction, todo, guard, and preset READMEs and JSDoc name the split and link this note in the same change.

## Risks

The handoff is a single quality hop: findings the child omits are unavailable to the parent, mirroring the unknown-unknowns risk recallable compaction records. The acceptance criteria's reconstruction diff detects size drift; content fidelity is the deployment's prompt responsibility, and the recallable backend remains the mitigation when handoffs prove too lossy. The child pays its internal re-reads at full price until provider implicit caching applies, so the split loses on small wind-ups with long wind-downs; the cost model in this note gives the cross-over, and the preset must not enable delegation by default for tasks below it. Guard classification of "discovery-class" versus "reading back a tool result to verify the fix" mislabels legitimate verify calls if it keys on tool names; it must classify by phase-relative intent (reading back one's own patch output is wind-down), and the executor-denial tests fix the borderline cases as they surface. Models trained on single-context transcripts may restate the handoff in wind-down turns, inflating output where the design intends hunks; the output-discipline segment and the per-turn output telemetry are the observation surface for that gap.

The preset must not enable the explorer category below the cross-over: under it the child's own full-price bill costs more than the echo it saves, and the Stage 4 report decides where the line sits per deployment — enablement above the cross-over, never always-on.

The read-only reader's failure mode is a truncated handoff: with no write surface there is no filed note recovering what the summary drops, and the recallable backend sits on the parent side, not the child's. The cheap non-thinking route is likewise an accuracy bet priced by the cross-over: the handoff-fidelity probe scores the cheap route against the thinking one, and the thinking route remains the configured fallback while the probe says it must. The per-turn cap trades a legitimate burst of parallel readers against spree protection; the configured cap is deployment judgment, and the reminder text on denial points at the handoff rather than silently absorbing the call.

The foreground wait trades user-visible latency for the flat echo: a slow route or a fat handoff ceiling leaves the parent idling in front of the user, so the Stage 0 report carries wall-clock per reader beside the token bill, and the handoff ceiling is the one knob bounding both.
