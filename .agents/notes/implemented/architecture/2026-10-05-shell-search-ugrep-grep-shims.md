# Agent Note: shell-search: vendor-npm ripgrep grep-family command shims for model shell calls

Status: implemented

## Problem

Agents running under this harness overwhelmingly search through the model-facing `bash` tool rather than the structured `grep`/`glob` tools, and no amount of prompt encouragement changes that: a single early successful `grep -rn` in a session sets an in-context precedent that out-weights system-prompt guidance for the rest of the session. GNU grep gives those agents its raw semantics — no ignore awareness in recursive mode, whole-line output that lets one minified hit flood the context, and silence where the corpus hides in ignored trees. The failures are environmental, and instruction-level fixes rot; the fix lives in the environment the child shell inherits.

The sourcing constraint is absolute: the owner publishes no binary packages and compiles nothing, so the replacement binary must ship as an ordinary vendor-published npm dependency. Verified against the registry on 2026-10-05: ugrep publishes no npm package at all (bare `ugrep` and every scoped variant 404) and its GitHub release v7.8.5 ships only `ugrep-windows-x64.zip`, so ugrep fails the constraint and is a deal-breaker despite being the best functional match (measured: GNU exit-code and `-q`/`-x` parity, default ignore-awareness, true `\n` adjacency, UTF-16 visibility, ~10x faster warm). What the registry does offer vendor-published: `@vscode/ripgrep@1.18.0` declares twelve `@vscode/ripgrep-<plat>` optionalDependencies, and in this checkout `node_modules/.pnpm/@vscode+ripgrep-linux-x64@1.18.0/.../bin/rg` is a live 5.5 MB ripgrep 15.0.0 executable — the binary rides as payload files in the platform package, independent of the main package's postinstall (which pnpm blocks here, leaving only its `bin/` empty).

Measured ripgrep versus GNU on this host (vendored 15.0.0 platform binary vs GNU 3.11) bounds what the shim imports from each engine. For ripgrep: warm recursion over `packages/` took 0.055s against GNU's 0.357s; a naive root recursion emitted zero `.gitignore`d-tree hits where GNU walks them; `--max-columns` replaced a 600-byte matched line with `[Omitted long matching line]` where GNU prints it whole; exit codes 0/1/2 and the shared flags `-q -c -l -i -n -o -w -v -x -m -A/-B/-C -e` behaved identically, lowercase patterns case-sensitive by default as in GNU. Two measured divergences draw the translation boundary: the pattern `a\+b` matched line 1 (`ab`, GNU BRE one-or-more) versus line 2 (`a+b`, ripgrep literal plus), and the identical argv `-rn bar d` made ripgrep substitute text under its replace vocabulary instead of recursing. Hygiene, truncation, ordering, and speed are what the wrappers take from ripgrep; the dialect and the verbs stay GNU's, preserved by the fail-open table.

## Decision

`packages/shell/shell-search` (`@deepseek-ai/dsh-shell-search`) is an opt-in function plugin beside `dsh-shell-env` that at boot generates POSIX sh wrappers named `grep`, `egrep`, and `fgrep` plus a Node translator under `<home>/shell-search/`, prepends the `bin` directory to the harness process `PATH` on POSIX, and contributes `DSH_SEARCH_BIN` to the managed shell environment. Command lookup is left-to-right first-match over the colon-separated `PATH` list, so the prepend shadows exactly the three grep-family names and nothing else. The wrappers exec the translator against the vendored ripgrep for `egrep` and `fgrep`; `grep` execs the host GNU grep verbatim because ripgrep has no POSIX BRE dialect ([routing supersession](../../proposed/architecture/2026-10-05-shell-search-dialect-routing.md)); any argv the fail-open table does not fully cover execs the host GNU grep unchanged, so scripts keep byte-identical semantics. The backend resolves at generation time by precedence: an explicit `rg` config path (failing loud when not executable), the installed `@vscode/ripgrep-<plat>` platform package selected by `process.platform`/`process.arch`, then `rg` on `PATH`, then the host grep fallback. The plugin injects `shell-env`; its placement — opt-in only versus shipped default — is decided by [2026-10-05-shell-search-ship-in-base.md](2026-10-05-shell-search-ship-in-base.md), which mounts it in `dsh-base` beside `dsh-shell-env`.

Application launch is untouched: the rule in [docs/architecture.md](../../../../docs/architecture.md#application-launch) forbids package bins, demos, and executables that become Node application launchers; runtime-generated shims reached through normal command lookup are plugin behavior, not launch paths, and the package ships no `bin` field.

## Implementation

`src/index.ts` owns the plugin surface: named exports `name`, `inject: ['shellEnv']`, `Config` (`dshHome`, `rg`), `PLATFORM_SUFFIX` mirroring the main ripgrep package's optionalDependencies names, `resolveRg`, `resolveBackend`, and `apply`. The `shellEnv` injection keeps the fiber PENDING until the managed-environment registry exists, so every composition boots `dsh-shell-env` first — the tests mirror that order. `apply` is a single `ctx.effect`: resolve, `mkdirSync`, write the translator and the three wrappers (0755), mutate `process.env.PATH` when not win32, `ctx.shellEnv.register` the `DSH_SEARCH_BIN` fact, and yield a disposer that unregisters, restores the exact prior `PATH`, and removes `shell-search/` recursively — so HMR and profile swaps unwind completely. Ripgrep resolution walks `createRequire(import.meta.url).resolve('@vscode/ripgrep')` then a nested `createRequire` to the platform package's `package.json`, then `bin/rg`, validating `X_OK`; the nested-require walk is the pnpm-safe mechanism verified in this checkout.

`src/shims.ts` owns the pure generators. Wrappers are one `exec` line with absolute paths baked in. The translation lives in a generated Node module rather than an inline `case` loop: POSIX sh cannot rebuild argv quoting-safely without sentinel tokens that a pattern argument could impersonate, while a Node helper takes structured argv, is trivially spawn-tested, and adds one interpreter hop only inside the shadowed names. The table, re-verified by spawned tests: `--include=G` → `--glob=G`; `--exclude=G` → `--glob=!G`; `--exclude-dir=D` → `--glob=!D/**`; `-r`/`-R`/`--directories=recurse`/`-d recurse` dropped (the discard rows exist because passing the stay verb behaved as measured above — verbatim pass-through would silently activate the replace vocabulary); `-E -F -i -n -l -c -o -w -q -v -x -s` verbatim; `-m/-A/-B/-C/-e` attached and spaced; `--` freezes the remainder. Translated invocations carry `--hidden --sort=path --max-columns=500`. A token outside the table, a value flag missing its value, or a ripgrep binary that fails to spawn at call time execs the host grep with the original argv and its exit code; the child's stdio and status pass through untouched. Policy needs no generated file: ripgrep reads `.gitignore`, `.ignore`, and `.rgignore` natively, and this repo's `.rgignore` already freezes the agent-notes archive.

## Testing

`tests/shell-search.spec.ts` spawns the generated wrapper under `sh` against a fixture tree with a `.gitignore`, a hidden directory, a 900-byte match line, and include/exclude targets, asserting grep-parity traversal over hidden and ignore-listed files, `[Omitted long matching line]` truncation, value-flag spellings, fail-open on `--unicorn=1` and on dangling `-m`/`-e`/`-d` (GNU exit 2 passthrough), fail-open on a bare directory operand, GNU `-E` reruns when ripgrep rejects a pattern, GNU reruns when the ripgrep binary fails to spawn, and 0/1/2 exit-code parity. Resolution tests pin the configured-path fail-loud, the vendored platform-binary default, `PATH` fall-through on an unknown platform, and the no-host-grep boot failure. Lifecycle tests boot the real `shell-env` registry and assert the wrapper files' execute bits, the `PATH` prepend, `DSH_SEARCH_BIN` in `ctx.shellEnv.list()`, the win32 skip, and full restoration of `PATH`, fact, and directory at disposal.

## Alternatives considered

**ugrep as the backend.** Best functionally: measured GNU exit-code and `-qx` parity, config-file globs, UTF-16, true `\n` adjacency, ~10x warm speed. Lost to the sourcing constraint: no npm package exists under any name and upstream ships no prebuilt Unix binaries, so shipping it would force owner-published platform packages or operator installs, both refused.

**Owner-published ugrep platform packages.** Re-running the esbuild pattern ourselves: CI static builds per pinned SHA plus a BSD-3 license allowlist row. Rejected by the owner's deal-breaker — the repo publishes no binary artifacts.

**Postinstall-download packaging** (the old `@vscode/ripgrep` mechanism): disproved locally — this checkout's main package `bin/` is empty because pnpm blocks scripts, which is exactly the silent broken-search failure mode a shell-provided binary must never have. The platform-package payload form supersedes it.

**A POSIX sh `case`-loop translation table.** The first sketch; discarded when argv rebuild required list sentinels that a caller pattern could impersonate, and every flag edge became an untested shell branch. The Node helper keeps the table structured and spawn-tested at the price of one interpreter hop.

**Structured `grep`/`glob` harness tools with better globs.** Tried and removed by the owner: agents do not use them regardless of encouragement. The problem was adoption, not capability.

**Instruction-level enforcement** (prompt rules, README notes, `--glob '!vendor/**'` idioms): attention-dependent and measured to rot within a session once bash grep succeeds once. Lost to the environment layer.

**A system-wide `/usr/local/bin/grep` replacement**: leaks to every human and script on the host and cannot carry per-repo policy; the generated per-deployment directory scopes the shadow to harness children only.

**ast-grep as the grep replacement rather than a complement.** Its npm sourcing is vendor-clean, but it is structural, not line-oriented: the agent's `grep -rn token .` habit wants a line engine, so ast-grep ships beside the ripgrep shim as the "where is X used" tier instead of replacing it.

## Consequences

- Model shell searches gain ignore hygiene, hidden-file visibility, sorted output, and line-flood truncation with zero caller cooperation, and degraded deployments fall back to byte-exact GNU behavior rather than failing.
- The shadow reaches every subprocess inheriting the mutated `PATH`, including harness scripts whose recursive grep must see ignored paths; the absolute-path escape hatch documents the contract without enforcing it.
- Regex dialect divergence is intrinsic and measured, not theoretical: on `ab\na+b\n`, GNU `grep 'a\+b'` yields line 1 (BRE one-or-more) and ripgrep line 2 (literal plus) — disjoint result sets no argv table reconciles. The table covers flags, not dialect; GNU dialect stays reachable through the escape hatch, and the agent's predominant exact-token searches are unaffected. Routing supersession: [shell-search dialect routing](../../proposed/architecture/2026-10-05-shell-search-dialect-routing.md) closes the `grep` half by execing the host GNU grep for that name (and removes the per-name mode tokens the original wrappers injected, which ripgrep rejected outright), leaving ripgrep to `egrep`/`fgrep` with `--no-ignore` traversal parity and exit-2 reruns under GNU.
- The mechanism depends on the `@vscode/ripgrep` platform-package payload surviving pnpm's blocked build scripts — the one installation form this checkout proves; a future main-package layout change to postinstall-only would degrade every deployment to the host-grep fallback and be visible as the `rg` tier going undefined in `resolveBackend`.
