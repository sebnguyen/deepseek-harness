# Agent Note: 在控制流上发布任务输出

Status: implemented

[English](2026-09-29-publishing-job-output-on-the-control-stream.md) | 中文

## 问题

Web 客户端只能列出某个 Session 的后台任务及其状态，别的都做不到：`jobs` 帧承载身份、kind、label、状态、时间戳与 detail。任务的输出只有模型能通过 `job_output` 取到，因此看着命令运行的人无法知道它在做什么——而这正是后台任务界面存在的理由。

控制流是合适的载体：它已经是推送式、按代重建的进程局部状态通道，`jobOutput` 不需要新的传输、store 或 Remote 命名空间。

## 决策

只要至少有一条控制流处于连接状态，Session 控制控制器就按配置的节奏（`jobOutputPollMs`，默认 250 毫秒；`0` 关闭发布）把每个可见任务的新输出行作为 `jobOutput` 帧发布。该帧携带这些行、其后的绝对索引，以及生产方是否在行被送出前就丢弃了它们。

发布通过 `ctx.jobs.readLines` 读取——正是为这个观察者新增的非消费式按行读取（见[在不消耗输出的前提下观察任务输出](2026-09-29-observing-job-output-without-consuming-it.zh.md)）。这正是让实时视图不去花掉模型 `job_output` 游标的原因：浏览器与 agent 通过两条互不相干的路径读取同一份保留输出。

单帧上限为 200 行，任务游标按实际送出的行数推进，因此大于一帧的突发输出会在后续 tick 继续，而不会被截断丢弃，也不会作为一帧无界数据发送。游标按任务、按控制器持有（而非按流），只在有流连接时推进，并且在流更替中存活：重新连接的流从边界处继续，而不是收到重放。

浏览器把这些帧镜像为按 Session 归属的每任务缓冲区，每个任务以 `JOB_OUTPUT_BUFFER_LINES` 为界，其中保存的是绝对的 `first`/`next` 索引而不只是行本身：因此视图可以判断更早的行已经离开缓冲区，并通过分页读取把它们取回；而起始行无法接续缓冲区的帧会重新锚定它，而不是把互不相干的行拼接到生产方已经丢弃的行之后。

浏览器渲染它所镜像的内容：任务行就是该任务自己的控件，选中它会在列表下方显示该任务的输出行。面板会在更早的行被丢弃时说明这一点，而不是把最新的行当作全部输出；它也会区分「还没有产生任何输出」与「输出只存在于模型的流中」这两种任务。Escape 每按一次退回一步——先面板，后列表——因为打开了两个东西的读者会期望按这个顺序关闭它们。

被截断的页会重新锚定：因为丢弃了行的生产方会报告 `truncated` 并返回它仍保留的内容，游标会移动到第一条保留行，且该帧被标记，于是消费方得知它已有的行并不连续到这一帧。

## 备选方案

- **把输出做成浏览器轮询的 Remote RPC。** 对实时输出而言拒绝：流本身已经存在，已经承载按 Session 的任务状态，也已经在重连时给出基线。浏览器里的轮询循环会引入第二个互不协调的时钟。
- **把累积输出放到 `jobs` 帧上。** 拒绝：该帧是可见*集合*，在每次注册、状态变化与结算时都会发送。携带大块文本会让每个生命周期事件都为输出付费，并且任何变化都会重发它。
- **让浏览器的缓冲区随任务增长。** 拒绝：一条打印一小时命令会让浏览器状态在整个运行期间持续增长。缓冲区保留最新的行，并说明其余部分在哪里。
- **按流各自持有游标。** 拒绝，因为这里的额外状态换不到东西。共享游标让每条已连接的流收到相同的帧，而按流游标本可服务的场景——一个视图打开时看更早产生的输出——属于回翻读取，而不是实时流。
- **把每条产生的行放在一帧里发布。** 拒绝：一条打印十万行的命令会作为一帧到达，而这一帧会推送给每条已连接的流。

## 后果

该节奏是部署成本——一次 tick 会读取每个可见任务的保留窗口——因此它是 `Config` 字段而不是常量，`0` 为更愿意按需读取的部署关闭它。

在流连接之前发布的输出不会重放给它，因此较晚打开任务详情视图的浏览器从边界处开始。它此时需要的是 `session/jobOutput({ sessionId, jobId, from })`，也就是与这条流并列的分页读取：它按绝对索引提供一页有界的保留行，并要求拥有任务的 Agent 处于活动状态，因为任务按所有者归属。两种机制分工明确——帧承载流实时看到的内容，分页读取承载回溯到最早保留行的内容。

已结算的任务仍会发布其尾部：发布遍历的是可见集合而不是运行中的任务，因此结算前刚产生的行会送达，而游标会在任务离开该集合后被清理。

## 验证

`packages/api/session-controller/tests/control-jobs.host.spec.ts` 针对真实控制器覆盖该路径：任务的行带推进的游标到达，随后发布归于安静；250 行的突发以有界帧到达，每行恰好按序送达一次；丢弃行的生产方给出被标记的帧，其游标重新锚定到缺口之后；节奏被禁用时不发布任何内容；而在流连接之前产生的输出仍会到达它，因为当时没有流连接，游标并未推进。`packages/client/ui-activity/tests/activity-dock.client.spec.tsx` 覆盖该视图：选中的 job 行带丢行提示显示该任务的输出行，未产生输出的任务显示空态文案，再次选中会收起详情，Escape 关闭抽屉，而离开镜像的任务会带走它的行。`packages/api/session-controller/tests/manager.client.spec.ts` 覆盖浏览器侧：连续的帧以绝对索引扩展任务缓冲区，出现被报告的缺口后的帧会重新锚定而不是拼接，超出缓冲区上限的突发保留最新的行并推进 `first`，而缓冲区会随其任务被丢弃，并在新一代中清空。`packages/api/session-controller/tests/job-output.host.spec.ts` 覆盖与之并列的分页读取：冷视图从最早的保留行开始读取、回翻到生产方仍保留的某一行、追平时得到 `lines: []`、一页有界且后续请求可继续、没有可寻址缓冲区的生产方被如实报告而不是显示为空、被报告的缺口令游标重新锚定，以及三种拒绝——没有活动 Agent 的 Session、不可读的任务、以及格式错误的游标。
