02 / Composition

What renders today

source · shipped

The slot tree

  • root single — the one shell hole
    • AppFrame — three-column CSS grid
      • sidebar → SidebarRoot (hover rail)
      • main keyed → conversation → ConversationPanel
        • main.conversation session-maybe → ConversationRoot
          • conversation.session session → ConversationSession → ChatView
          • conversation.composer.bar session-maybe → InputBar
          • conversation.session.header session
      • rightbar → SidebarRight (ui-dockkit split tree)
      • shell.overlay list — portals

Why one cell is easy, and N cells is not

  • one mainThe keyed main slot selects exactly one entry. There is no second conversation mounted.
  • one currentuiSession.currentBinding follows the single dsh.sessions.current pointer; every session-scoped outlet reads the ambient binding.
  • declared onceThe Conversation plugin declares the session surface once in registerConversationRoot. The slot core allows one declarer per slot, so a new grid entry cannot declare main.conversation again.
  • focusInputBar refocuses on mount and the plugin refocuses the current Session on activation. N composers would contend.
  • weightA populated window is about 3.8k elements; the transcript virtualizes, but nine live cells still need a profile and a cap.
03 / Proposal

How Turbo composes

pinned seat · unused

Swap the shell, keep the cells

AppFrame is the switch. It already owns the root registration and the grid, so Turbo is a branch, not a second app: do not render the normal sidebar or rightbar; render a fixed 56px Turbo sidebar with only the exit control, and fill the center with a new root-scoped turbo slot.

The grid never declares the conversation. The frame passes its own renderSlot('main', …, { entryKey: 'conversation' }) down as an owner prop. Each cell wraps that call in the framework's named-session seat:

// TurboGrid — one cell
<PinnedSessionProvider sessionId={cell.sessionId}>
  {renderConversation()}
</PinnedSessionProvider>

Why it works: the seat is a React context override, not a second slot declaration. The main.conversation outlet renders under the provider, so it and every session-scoped child below it read the named binding. The ambient current selection keeps following the real one outside the cell.

The Turbo tree

  • root single
    • AppFrame — turbo branch
      • turboSidebar — fixed 56px, exit only (new)
      • turbo single → TurboGrid (new)
        • cell A → cellRail (useSessions) + PinnedSessionProvider → main → conversation (session A)
        • cell B → cellRail (useSessions) + PinnedSessionProvider → main → conversation (session B)
        • cell C → cellRail (useSessions) + PinnedSessionProvider → main → conversation (session C)
      • sidebar — not rendered while Turbo is on
      • rightbar — not rendered while Turbo is on
  • statecolumns[] and rows[] are fraction weights written to grid-template-*; memory-only, like the dock layout.
  • create+ calls sessions.create(), then open(). It does not reuse a blank session, so every new cell is distinct.
  • railEach cell's left rail opens a scoped useSessions list with search and New Session. Choosing a conversation writes only that cell's id and calls openSession; a session already in another cell focuses that cell.
  • sidebarThe global SidebarRoot is not mounted in Turbo: its actions and workspace tree are global. The cell rail is scoped, and the fixed Turbo sidebar only exits.
  • focusOnly the current Session's composer autofocuses; clicking a cell calls uiWorkspace.openSession.
  • exitThe fixed Turbo sidebar's exit restores the normal sidebar, frame, and previous main panel; the right panel's dock layout lives outside the frame.

05 / Cost

What it costs, and what can bite

estimates · not a schedule

Slices

SliceShipsRough cost
1Button, mode state, frame swap, one live cell4–6 h
2Grid rows/columns, + controls, resize, cap6–10 h
3Independent Sessions per cell, per-cell rail, focus, create/open1–2 d
4Close, reorder, recent-conversation palette, persistence, lazy transcriptdeferred

The first two slices are the visible prototype. Slice 3 is the product step, and it is gated on a spike: the pinned seat is tested for direct session children, not yet for the keyed main outlet.

Risks

Pinned-seat composition

Prove renderSlot('main') inside the provider resolves main.conversation and the composer against the named Session. Fallback: a dedicated session-scoped cell slot owned by ui-conversation.

Focus and shortcuts

The current Session is global. Gate autofocus, select on cell click, and keep the normal shell unchanged.

DOM cost

Nine live cells can mean tens of thousands of elements and several animated pixel loaders. Cap, use content-visibility, and profile before raising the cap.

Empty sessions

+ creates Sessions that appear in the list even if unused. Consider create-on-first-send or a close-cell sweep later.

Small cells

Below roughly 360×280 the header, rail, width handles, and composer break. A compact cell treatment is required before shipping.

The right panel leaves

Turbo drops the docked file preview and IDE pane. The mode is presentation-only; exit restores the column and its layout.

Rail scale

Every cell carries a session list; a long roster times nine cells is a real cost. Filter locally, mount only the open panel, and avoid a full WorkspaceBrowser per cell.

Duplicate sessions

Two cells on one Session share one composer editor. The rail focuses the existing cell; the grid enforces one cell per Session.

No global sidebar

The normal New Session and Turbo Mode button are absent in Turbo. The fixed Turbo sidebar's exit and the per-cell New Session must cover both.
